## 3.1 项目背景与业务价值

**一句话定位**：面向非技术用户的自然语言数据分析 Agent，输入问题 → 自动生成 SQL + Python 分析 + 可视化报告。

**业务价值**：
- 降低数据分析门槛：运营/产品人员用自然语言提问，无需写 SQL/Python
- 企业级 Agent 架构：多 Agent 隔离、RAG 知识增强、Human-in-the-Loop、安全执行
- 渐进式复现：从 Java/Spring AI 架构完整迁移到 Python/LangGraph，验证跨语言架构一致性

**技术栈**：
- FastAPI + LangGraph + MySQL + ChromaDB + Docker + OpenAI 兼容 LLM
- 195 个自动化测试（单元 + 集成 + 回归）

## 3.4 核心技术取舍

| 技术决策 | 选择 | 替代方案 | 取舍理由 |
|---------|------|---------|---------|
| **工作流引擎** | LangGraph StateGraph | Temporal / Prefect / 自研 | interrupt 原生支持人机协同；checkpointer 持久化恢复；Python 生态标准 |
| **流式协议** | SSE (text/event-stream) | WebSocket / gRPC stream | 对齐 Java 已有协议，前端 EventSource 零成本 |
| **向量数据库** | ChromaDB (本地 PersistentClient) | PGVector / Elasticsearch / Milvus | 开箱即用，无额外依赖 |
| **代码执行** | Docker 沙箱 (P0 已实现) | Local subprocess / WASM | 安全隔离：内存限制+网络隔离+只读FS+非root |
| **状态持久化** | SqliteSaver (P0 已实现) | MemorySaver / PostgresSaver | 跨重启恢复，可配置切换 |
| **SQL 安全** | 白名单校验 (P0 已实现) | 只读账户 / 语法解析 | 多层防护：只允许 SELECT/WITH/EXPLAIN，拦截 DDL/DML/DCL |
| **LLM 调用** | AsyncOpenAI 兼容协议 | LangChain / LlamaIndex | 减少依赖层级，直接 API 可控性更高 |
| **HumanFeedback** | LangGraph interrupt + Command(resume) | 自建状态机 + Redis 等待 | 图暂停/恢复语义清晰，不需要额外状态存储 |

## 3.5 难点与优化

### 1. PlanExecutor 循环调度设计

**难点**：不是线性 DAG，PlanExecutor 被反复进入，需正确递增 step 编号，避免无限循环。

**方案**：每个流水线末端节点（sql_execute / python_analyze）负责递增 `plan_current_step`；PlanExecutor 只做路由决策。

**关键文件**：`workflows/nodes/plan_executor.py` + `workflows/graph.py`

### 2. 自循环重试机制

**难点**：LangGraph 中实现 node → self 的条件边模拟重试，避免无限重试。

**实例**：
- SQL 生成失败 → `sql_generate` 自循环（max 10 次），超限 → END
- Python 执行失败 → `python_generate` 自循环（max 5 次），超限 → 降级到 analyze
- TableRelation 异常 → 自循环（max 3 次），超限 → END

### 3. SQL 安全校验（P0 补齐）

**难点**：LLM 生成的 SQL 可能包含注入、危险操作、多语句。

**方案**：执行前强制校验：
1. 剥离注释和字符串字面量（避免误判）
2. 白名单检查前缀（SELECT/WITH/EXPLAIN/DESCRIBE/SHOW）
3. 危险关键字扫描（DDL/DML/DCL/危险函数）
4. 分号检测（防堆叠注入）

### 4. 代码安全执行（P0 补齐）

**难点**：LLM 生成的 Python 代码不可信，可能读文件、访问网络、消耗资源。

**方案**：Docker 沙箱隔离：
- 内存限制 512M + CPU 单核
- 网络隔离 (`--network none`)
- 只读根文件系统 (`--read-only`)
- 非 root 用户 (`--user 1000:1000`)
- 禁止提权 (`--security-opt=no-new-privileges`)
- 超时 60s

### 5. 状态持久化（P0 补齐）

**难点**：MemorySaver 在进程重启后丢失所有 HumanFeedback 等待中的状态。

**方案**：默认使用 SqliteSaver 持久化到文件，支持跨重启恢复。通过 `settings.checkpointer_type` 配置切换。

## 3.6 字节面试追问清单

| 追问方向 | 回答要点 |
|---------|---------|
| **为什么用 LangGraph 而不是自研？** | interrupt 原生支持 Human-in-the-Loop；checkpointer 持久化/恢复；生态兼容 LangSmith |
| **PlanExecutor 如何处理步骤间数据依赖？** | WorkflowState 全局字典传递；SQL 结果写入 sql_result → Python 节点变量注入 |
| **如何保证 SQL 安全？** | 白名单校验器：剥离注释+字符串 → 只允许 SELECT/WITH/EXPLAIN → 拦截 DDL/DML/DCL → 防分号堆叠 |
| **Python 代码执行安全性？** | Docker 沙箱：512M 内存限制 + 网络隔离 + 只读 FS + 非 root + 超时 60s |
| **多 Agent 如何隔离？** | 数据库级：独立 datasource + 独立 ChromaDB collection（agent_{id}_knowledge） |
| **如何处理 LLM 输出不稳定？** | SemanticConsistency 语义校验 + 最多 10 次重试 + 结构化 JSON 输出验证 |
| **如何评估模型效果？** | 46 个 test cases / 4 级难度 / SP(语法)+EM(匹配)+EX(执行)+VES(效率) |
| **大表查询性能？** | 当前：无优化；规划：SQL 结果采样 + 大结果集转文件下载 |
| **为什么对齐 Java 协议？** | 团队已有 Java 前端；协议对齐 = 零前端改动 = 渐进迁移 |
| **状态持久化怎么做的？** | SqliteSaver checkpointer；HumanFeedback 暂停后重启也能 resume |
