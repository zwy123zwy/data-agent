# Phase 2: 面试适配评估

> 评估日期：2026-05-09
> 项目版本：v0.2.0（P0 短板已补齐）

## 评估结论

**适合作为字节面试展示项目。建议采用「架构讲解 + 现场演示 + 录制备份」三轨策略。**

工程完整度超过"仅技术讨论"门槛，可覆盖字节 AI Agent / 数据智能 / 后端工程多个面试方向。

## 短板与风险（P0 已补齐后）

| 类别 | 当前状态 | 面试影响 |
|------|---------|---------|
| **端到端联调** | 前端为 Java 前端（Vite :3000），Python 需独立启动 | 演示需启动多个进程 |

| **水平扩展** | 单进程 + MemorySaver/SqliteSaver | SqliteSaver 说明已向持久化演进 |
| **演示稳定性** | 依赖 LLM API + MySQL + Ollama | 建议准备录屏备份 |

## 面试展示策略

1. **优先展示架构设计**（最体现工程能力）
   - StateGraph 拓扑图 → PlanExecutor 循环调度 → 重试机制设计
   - 展示 `workflows/graph.py` 的条件边和自循环

2. **其次展示安全设计**
   - SQL 安全校验器（白名单机制 + 危险关键字拦截）
   - Docker 执行器（内存限制 + 网络隔离 + 只读文件系统）

3. **然后展示代码质量**
   - StateKeys 常量（对齐 Java Constant）
   - 节点注释体系（每个文件有完整的"在系统中的地位"段落）
   - 三层错误处理（节点级 → 工作流级 → API 级）

4. **最后现场演示**
   - SQL 查询 → Python 分析 → 报告生成 → HumanFeedback
   - 准备录屏视频防止现场网络/API 问题

## 面试可能追问方向

| 方向 | 回答要点 |
|------|---------|
| 为什么用 LangGraph 而不是自研？ | interrupt 原生支持人机协同；checkpointer 支持持久化恢复；生态兼容 LangSmith |
| PlanExecutor 如何处理步骤间数据依赖？ | WorkflowState 全局字典；SQL 结果写入 sql_result → Python 节点变量注入 |
| 如何保证 SQL 安全？ | 白名单校验（只允许 SELECT/WITH/EXPLAIN 等） + 危险关键字拦截（DDL/DML/DCL） |
| Python 代码执行安全性？ | Docker 沙箱：内存限制 512M + 网络隔离 + 只读 FS + 非 root + 超时 60s |
| 多 Agent 如何隔离？ | 数据库级：独立 datasource + 独立 ChromaDB collection（agent_{id}_knowledge） |
| LLM 输出不稳定怎么办？ | SemanticConsistency 语义校验 + 最多 10 次重试 + 结构化 JSON 输出验证 |
| 如何评估模型效果？ | 46 个 test cases / 4 级难度 / SP+EM+EX+VES 指标 |
| SSE 断开重连？ | SqliteSaver 持久化状态；前端重连带 threadId → resume 继续 |
| 为什么对齐 Java 协议？ | 团队已有 Java 前端；协议对齐 = 零前端改动 = 渐进迁移 |
